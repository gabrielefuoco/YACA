## FEATURE RISK

- **Cache & Redis (Findings 2, 4, 5):** Fixing `tmdbDetailsCache` write-back on EN/original fallback changes cached payload language from raw IT-only to merged IT/EN/orig — safe and intended, provided `ttl` stays bounded for ongoing series. Setting `ramMax > 0` on `catalogRequestCache` increases Node heap slightly (~2-5 MB for 150 catalog pages of 20 items) inside `mem_limit: 1536m`; keep `ramMax` <= 150-200. Removing `erdbHeadCache` / `/images/fallback` only breaks legacy clients if any still hold old `/images/fallback` URLs in Stremio library (none generated by current `src/`).
- **Poster Volume & `sorgenti.json` (Finding 6):** Changing `posterFileName` source-token storage (e.g. moving `sorgenti` to Redis or stopping the 200k reset) must preserve existing token lookups for already-rendered files in `/data/erdb-cache` or existing poster URLs will miss cache until re-rendered by ERDB.
- **Sync & `idMapping` (Findings 3, 10):** Replacing sequential `resolvePoster` / `enhanceTraktItem` with batched DuckDB + `tmdbDetailsCache` keeps identical Stremio metadata fields while eliminating N+1 Mongo/TMDB storms. Ensure `rateLimitedMap` concurrency remains <= 5 for TMDB fallback calls to avoid 429s.
- **Anime Mapping (Finding 11):** `buildFribbIndex`, `buildAnibridgeIndex`, and `loadOverrides` are called by 9 test files in `tests/` (`tests/anime*.test.js`, `tests/itaFallbackTipoAnimeBadge.test.js`, `tests/schedaPosterCacheIta.test.js`), so keep those test helpers or move them to a test helper before deleting from runtime.
- **Budget Tracker (Finding 1):** `services/tmdb-daemon/tmdbDumpClient.js:242,247` and `services/tmdb-daemon/tests/tmdbDumpOutcome.test.js` import `tmdbBudget` / `TMDB_CATEGORIES`; removing `tmdbBudget.js` outright requires updating those two files, whereas removing only the `tmdb.js` axios interceptor and unused `executeWithBudget`/`DECLARED_TTLS`/`getMetrics` preserves daemon tests untouched.
