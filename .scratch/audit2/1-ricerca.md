## FEATURE RISK

- **Skipping `rawTMDB.credits` / `rawTMDB['watch/providers']` in `mapDuckDbRowToMeta` (`duckDbProvider.js:255-271`)**: `MetadataHydrator.js:89` reads `mappedMeta.rawTMDB?.credits?.cast` when hydrating hybrid/hero catalogs via `mapDuckDbRowToMeta`; keeping an `includeCredits` option (default `false` for search/preset catalogs, `true` for `MetadataHydrator` and `getDuckDbMetaDetails`) avoids breaking hybrid/taste hydration while keeping the 5× `JSON.parse` win on search/catalog hot paths.
- **Serving `door.cerca({ tipo: 'genere' })` from `FALLBACK_GENRES` instead of TMDB (`/genre/*/list`)**: If TMDB ever adds a new genre ID or changes an Italian genre translation, users of the creator autocomplete wouldn't see it until `generi.js` is updated (and `door.cerca` currently merges `movie` + `tv` lists, which adds TV-only genres like `10759 Action & Adventure`, `10762 Kids`, `10763 News`, `10764 Reality`, `10765 Sci-Fi & Fantasy`, `10766 Soap`, `10767 Talk`, `10768 War & Politics` that `FALLBACK_GENRES` omits — easily preserved by including TV-specific entries in `generi.js` or keeping live fetch with long cache).
- **Skipping TMDB `/search/multi` in `door.cerca({ tipo: 'titolo' })` when `localCandidates.length >= limit`**: If a user searches an obscure/newly released title whose local Tier 1 + Tier 2 matches already fill 20 popularity/BM25 slots with unrelated partials, omitting TMDB `/search/multi` could hide a brand-new release not yet in the daily export.
- **Switching `door.cerca({ tipo: 'persona' })` to local `people.db`**: `people.db` returns `{ tmdbId, name, ruoli, titoli }` without TMDB's `profile_path` or `known_for`, and omits people with 0 titles in the local parquet dump; any creator UI displaying actor avatars from `/api/ricerca?tipo=persona` would lose thumbnails.
- **Short-circuiting `searchTier2` on `skip > 0` or `kidsMode` in `ricercaUnificata.js` / `catalogHandler.js`**: On `skip > 0`, users scrolling past page 1 of a text search that has <20 Tier 1 matches will get 0 Tier 2 results instead of repeated page-1 Tier 2 results (an improvement, unless Tier 2 itself implements `OFFSET skip` via FTS5 `LIMIT ? OFFSET ?`); under `kidsMode`, stopping `catalogHandler` pagination after 1 search call avoids 4× redundant work, and passing `genres`/`genre_ids` or relaxing fail-closed only after enrichment keeps kid-safe Tier 2 hits visible.
- **Removing `F.genreStr`, `F.keywordStr`, `F.director`, `F.shortFilm`, `F.releasedAfter`, `F.airedAfter`, `G.mapGenres`, `fondiEOrdina`, `numeroId`, `duckDbProvider` sort exports**: Zero production `src/` impact, but existing Jest specs (`duckDbAndMatchmaker.test.js`, `heroMovieDateRegression.test.js`, `resilienceAuditFixes.test.js`, `filtroDurataIgnota.test.js`, `ticket15.dnaFixes.test.js`, `ricercaDoor.test.js`, `risolutori.test.js`, `presetsSorting.test.js`) and `scripts/qa/catalog-audit.js` call these symbols directly and would need simultaneous updates.

## Summary

- **Estimated net code reduction**: ~345 lines across `src/ricerca/**` and `src/indice/{filters,duckDbProvider,tier2,people,keywordIds}.js` (with zero feature loss if guarded as noted above).
- **Top bottlenecks**: (1) `tmdbDetailsCache.set` running *before* linguistic fallback in `getTmdbMetaDetails`, causing 20–40 live TMDB HTTP calls even on warm-cache Tier 2 searches; (2) `semiTitoli.cercaSeme` running multiple 150k–200k linear JS scans + 300k string allocations + 50k-word Levenshtein, multiplied by `risolviLista` on multi-seed `simili`; (3) `semiDaGrafo` hydrating 100 full DuckDB rows (700 `JSON.parse`s + `uniqueById` window sort) to slice 20; (4) `candidatiLocali` + `kidsMode` repeating sequential/unpaginated Tier 2 + `enrichTier2Items` up to 4×; (5) N+1 `learnNames` SQLite transactions per enriched item.
